# RA-054 — Codex subscription live compatibility repair

**Status:** DONE
**Zależy od:** RA-053
**Milestone:** M10 — `ADR-0016`

## Cel

Naprawić wykryte live niezgodności oficjalnego `codex` zalogowanego subskrypcją
ChatGPT tak, aby provider-neutralna ścieżka Engineering przechodziła minimalny,
bezpieczny smoke test bez API key, fallbacku i dostępu do repozytorium. Na czas
diagnostyki zwiększyć kodowy budżet tokenów Engineering trzy razy, bez zmiany
wyboru modelu ani providera dla którejkolwiek roli.

## Kryteria akceptacji

1. Preflight wspiera dokładny, aktualny kontrakt `codex login status`, w którym
   pojedyncza dozwolona linia może pojawić się na stdout albo stderr, lecz
   odrzuca oba kanały naraz, wiele linii, API-key mode i nieznany status.
2. Code-owned response schema jest zgodna ze strict structured output Codex:
   wszystkie własne `const` i `enum` mają jawny typ, a digest nadal wiąże exact
   output oraz tool definitions.
3. Model nie jest hardcodowany do roli. Opt-in smoke wymaga jawnego modelu i
   canonical executable, działa w pustym ephemeral root, read-only, bez tooli,
   shell, web, MCP, subagentów i workspace.
4. Diagnostyczny budżet całego wywołania Engineering ma jawny mnożnik `3`:
   target `750000`, warning `1200000`, hard limit `1800000`, rezerwa następnego
   wywołania `105000`; journal nadal raportuje exact zużycie i granice.
5. Realny opt-in smoke przez produkcyjny preflight i transport, zalogowany
   ChatGPT subscription, zwraca exact structured result i content-free usage;
   nie wykonuje commita ani zewnętrznego write.
6. Mutation checks czerwienią stderr auth compatibility, mixed-channel auth,
   typed schema envelope, mnożnik budżetu i odłączenie live smoke od realnego
   transportu.
7. Pełna niecache'owana bramka, audyt i workflow validation kończą się exit `0`.
