# RA-008 — Checkpoints, context and decisions

## Goal

Zapewnić ciągłość one-shot agentów oraz trwałe, bezpieczne pytania decyzyjne.

## Scope

- versioned `CaseCheckpoint` repository i optimistic revision;
- context builder: task, thread excerpt, checkpoint, entities, receipts, plan,
  repo state i dozwolone tools;
- budżet kontekstu, deterministyczne priorytety i provenance;
- atomic apply `AgentCompletion` -> checkpoint/run/outbox;
- `WAITING_FOR_USER`, `DecisionRequest`, answer binding i stale-answer rejection;
- renderer Markdown/pinned Discord status;
- compaction jako derived data, bez usuwania autorytatywnych decyzji;
- recovery niedokończonego model call zgodne z RA-004.

## Out of scope

Pełny role orchestrator i coding workspace.

## Acceptance criteria

1. Nowy run odtwarza wszystkie materialne decyzje bez poprzedniej model session.
2. Dwa równoległe completion nie mogą nadpisać nowszego checkpointu.
3. Odpowiedź na stare/obce pytanie jest odrzucona.
4. `WAITING_FOR_USER` nie utrzymuje procesu ani lease bez potrzeby.
5. Rendered Markdown jest projekcją i nie może nadpisać JSON source of truth.
6. Context builder nie miesza entities z różnych connection scopes.

## Required verification

- integration tests crash przed/po atomic checkpoint apply;
- golden tests context selection i Markdown rendering;
- tests context budget, stale revision i decision replay.

## Audit focus

Utrata informacji przy compaction, provenance, optimistic concurrency oraz
możliwość wznowienia wyłącznie z danych trwałych.
