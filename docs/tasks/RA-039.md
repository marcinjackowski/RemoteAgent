# RA-039 — Generyczne structured output dla etapów Bedrock

**Status:** DONE
**Zależy od:** RA-037  
**Milestone:** M8 — `ADR-0011`

## Cel

Usunąć założenie, że każdy model call zwraca globalny `AgentCompletion`, i
udostępnić schema-owned transport dla kontraktów product/design/plan/review/
verification bez tworzenia nowego klienta Bedrock.

## Zakres

- Generyczne `runStructured<TSchema>()` albo równoważny typed adapter nad
  istniejącym tool-loopem.
- Jawne schema name/version/digest, parser, repair instruction i metadata.
- Stage-specific bounded repair oraz osobna semantyka dla read-only decyzji i
  implementera.
- Pin model/provider identity, prompt version i usage metadata.

## Kryteria akceptacji

1. Ten sam transport obsługuje co najmniej dwa różne strict schemas bez globalnej
   zależności od `AgentCompletion` i bez `unknown` cast omijającego walidację.
2. Wynik wiąże model identity, stage, schema version/digest, request ID, usage,
   liczbę transport calls i informację o repair.
3. Malformed output ma bounded, tools-off repair dla etapów read-only; malformed
   implementer report nie uruchamia ponownie edycji jako naprawy JSON.
4. Mismatch modelu lub schema digestu jest fail-closed; obie ochrony mają
   mutation RED→GREEN.
5. Abort/timeout nie jest raportowany jako zwykły invalid JSON i propaguje
   rozróżnialny rezultat operacyjny.
6. Istniejący reply-loop oparty na `AgentCompletion` pozostaje kompatybilny.
7. Bramka taska i `workflow:validate` kończą się exit code `0`; live AWS nie jest
   obowiązkową bramką.

## Nie w scope

Wybór źródeł kontekstu, orchestration stages, gates i workspace writes.

## Stan przygotowania — 2026-08-26

- Bazowy commit: `750b1479197943e7b5f7db587d7092f0aff1ecac` (RA-038 DONE).
- Nowe API jest schema-owned: jeden obiekt Zod jest jednocześnie parserem typu
  wyniku i źródłem JSON Schema/canonical digest. Runtime nie przyjmuje osobnego
  parsera i schema JSON, które mogłyby się rozjechać.
- Model identity jest sprawdzane na każdej odpowiedzi transportu przed parsowaniem
  i przed wykonaniem tool-use. Expected schema digest jest porównywany przed
  pierwszym transport call.
- Polityka repair wynika z durable `EngineeringStage`: read-only stage ma najwyżej
  jeden tools-off repair; `SLICE_IMPLEMENTATION` nie uruchamia modelu ponownie po
  malformed report.
- Istniejące `runStructuredCompletion`/`runAgentCompletion`, `Runtime` structured
  mode i worker reply-loop zachowują kontrakt `AgentCompletion`.
- Kroki: `docs/work-units/RA-039/WORK_UNITS.md`.
