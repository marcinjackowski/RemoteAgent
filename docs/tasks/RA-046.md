# RA-046 — Engineering approval ingress: Discord → grant → writer job

**Status:** DONE
**Zależy od:** RA-044
**Milestone:** M8 — `ADR-0014`

## Cel

Udostępnić produkcyjny, server-owned sposób rozpoczęcia high-risk engineering runu bez ręcznych
insertów DB: propozycja ma zostać pokazana ownerowi w Discordzie, a exact grant atomowo utworzyć
istniejący `engineering_approval` consumer payload i jeden writer job.

## Kryteria akceptacji

1. Proposal jest strict/versioned i trwale wiąże case, owner, checkpoint revision, work unit, run,
   process class, repo/write ceiling oraz canonical action digest; model i Discord payload nie
   dostarczają authority fields.
2. Produkcyjny Discord composition root routuje code-owned `GRANT`/`DENY`/`STOP` zamiast ACKować i
   porzucać non-message outcomes.
3. `GRANT` w jednej transakcji ponownie wyprowadza scope, zapisuje exact Approval, claimuje
   prealokowany work unit/run i enqueue'uje jeden `agent.implementer` z
   `reason=engineering_approval`; replay zwraca te same durable ID.
4. `DENY`, stale revision, foreign owner/case, zmieniony scope, expired proposal, double click i
   crash przed/po outbox nie tworzą dodatkowego grantu, runu ani joba.
5. Generic `DecisionAnswer`, modelowe option ID i `external_actions` nie mogą autoryzować engineering
   write; mutation każdego bypassu daje RED.
6. Realna integracja przechodzi Discord intake → persistence/outbox → grant → worker consumer bez
   bezpośredniego testowego `ApprovalRepository.grant`/`jobs.enqueue`.
7. PostgreSQL tests używają `RA_REQUIRE_POSTGRES=1`; pełna bramka, audyt i
   `workflow:validate` kończą się exit code `0`.

## Poza zakresem

Owner review konkretnego `ProgramDesign`, push/MR/merge oraz live Xcode.
