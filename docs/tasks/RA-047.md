# RA-047 — Stage-aware cross-fence recovery i continuation

**Status:** DONE
**Zależy od:** RA-046
**Milestone:** M8 — `ADR-0014`

## Cel

Kontynuować engineering run po rzeczywistym lease expiry/reap bez ponawiania nieznanego write i
bez ręcznej edycji DB. Recovery ma używać stage-specific durable evidence, a generic queue/fencing
pozostaje fail-closed.

## Kryteria akceptacji

1. Expired partial engineering job jest podejmowany wyłącznie w code-owned recovery mode; zwykły
   claim/retry nie poszerza authority i nie uruchamia stage przed klasyfikacją.
2. `READ_ONLY`/`MODEL_CALL` może zostać ponowiony tylko przy exact immutable descriptor,
   config/schema, scope i current writer binding; mutating classes bez dowodu pozostają
   `AMBIGUOUS`/`RECONCILING`.
3. GATE po outer crash składa ten sam `EvidenceBundle` wyłącznie z exact durable per-gate receipts;
   żaden completed command nie jest dispatchowany ponownie, a STARTED/no receipt blokuje.
4. LOCAL_COMMIT recovery jest observe-only: exact HEAD/parent/marker/tree/diff daje jeden receipt i
   łącznie jeden commit; mismatch pozostaje niejednoznaczny.
5. Naprawa artifact/completion/observation starej operacji używa dedykowanej current-lease-fenced
   granicy; generic JobStore/append API nie akceptuje dowolnego fence rollover.
6. Durable continuation zachowuje case/work unit/run, ordered artifact history, budgets i
   cancellation/deadline; dwa recovery workery nie tworzą dwóch writerów ani dwóch continuation.
7. Fault matrix obejmuje crash przed/po intent, STARTED, effect receipt, artifact, completion,
   observation i enqueue continuation dla model/gate/commit; safety mutations dają RED.
8. Pełna bramka z realnym PostgreSQL/Git/process, audyt i `workflow:validate` kończą się exit `0`.

## Poza zakresem

Replay niepotwierdzonego narzędzia/commandu, operatorowe „assume success” bez dowodu oraz push.
