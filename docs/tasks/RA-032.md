# RA-032 — Model runtime: agent myśli i odpisuje (Bedrock + config w DB)

## Goal

Uruchomiona rola (z RA-031 materializowany PENDING SUPERVISOR unit) faktycznie **woła model
Bedrock**, widzi wiadomość właściciela w kontekście i **odpisuje w wątku Discorda**.

## Decyzje właściciela (2026-08-24)

- **Backend: Bedrock bezpośredni** (`AwsBedrockTransport`, RA-007) — zwraca bloki tool-use, więc
  RemoteAgent mediuje narzędzia (warunek RA-033). NIE agentowe CLI (własna pętla → omija policy).
- **Auth: bearer token.** `AWS_REGION` + `AWS_BEARER_TOKEN_BEDROCK` (bez kluczy IAM/SigV4). Zweryfikowane:
  zainstalowany `@aws-sdk/client-bedrock-runtime@3.1113.0` **nie** auto-czyta `AWS_BEARER_TOKEN_BEDROCK`
  (string nieobecny w store; jest schemat `httpBearerAuth`, token trzeba podać jawnie). Więc transport
  musi to wpiąć.
- **model_id: DB server config**, nie env. Mała tabela `agent_config`, rozwiązywana przy dispatchu;
  env (`BEDROCK_MODEL_ID`/`RA_MODEL_ID`) tylko jako bootstrap-default. Server-owned (model nie wybiera
  sam siebie).

## Kryteria akceptacji

- **AC1:** `agent_config` (DB) z `model_id`; repo get/set; rozwiązywanie model = DB → env → bezpieczny
  default. Migracja + test. Server-owned.
- **AC2:** `AwsBedrockTransport` uwierzytelnia bearer tokenem gdy `AWS_BEARER_TOKEN_BEDROCK` ustawione
  (przekazany jako `token` do `BedrockRuntimeClient`); inaczej domyślny łańcuch. Region z `AWS_REGION`.
  Test (klient budowany z tokenem, gdy env obecny).
- **AC3:** Agent WIDZI wiadomość. Odkrycie (`2026-08-24`): `createRole.invoke` (`roles.ts:47`) wysyła
  do modelu **tylko objective** — kontekst (`buildContext`/`thread_excerpt`) NIE jest wpięty w
  wywołanie roli. Więc to nie „emisja fragmentu", lecz **wpięcie kontekstu w inwokację roli**:
  createRole czyta ostatnie `case_messages` case'a i przekazuje je jako UNTRUSTED (osobno od
  trusted objective). Wiring testowalny FakeTransportem (wiadomość dociera do modelu); jakość
  odpowiedzi — dopiero live (AC5). To zmiana rdzenia inwokacji, blisko RA-033.
- **AC4:** Projekcja completion → Discord: `run_completions` emituje outbox `aggregate:"case"`; dodać
  projekcję na `discord_case` `thread_message`, żeby odpowiedź agenta wróciła do wątku (relay z RA-029).
  Test: completion → wiersz discord_case thread_message.
- **AC5:** Smoke na żywo. **BLOKADA wykryta na żywo (`2026-08-24`):** bearer auth + dostęp do modelu
  działają (plain converse `us.anthropic.claude-opus-4-8` → „READY"), ALE strukturalny output przez
  `outputConfig` w `AwsBedrockTransport` (RA-007) jest **odrzucany przez Bedrock**
  (`ValidationException: output_config.format: Extra inputs are not permitted`). Każda rola używa tej
  ścieżki, więc live rola failuje. **Zweryfikowany fix:** structured output przez **wymuszone
  narzędzie** (toolConfig + toolChoice) — raw test `toolUse.input={"answer":"Hello!"}` OK. To defekt
  RA-007 (transport nigdy nie był sprawdzony wobec żywego Bedrocka — wzorzec CTF-018). Wymaga
  przeróbki `AwsBedrockTransport.converse`/`responseContent` (outputConfig → tool-use). Dopiero potem
  live SUPERVISOR odpisuje w wątku.
- **AC6:** Bramka zielona (Node 24), typecheck/build/lint/format, przebiegi.
