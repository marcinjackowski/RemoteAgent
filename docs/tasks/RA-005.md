# RA-005 — Connections, secrets and scope isolation

## Goal

Utworzyć bezpieczny model połączeń dla wielu kont i repozytoriów bez ujawniania
credentiali agentom.

## Scope

- `Connection` z provider, owner, alias (`private`, `sondermind`) i capabilities;
- secret reference zamiast tokenu w DB/logach;
- interfejs credential vault: lokalny test adapter oraz AWS Secrets Manager/KMS;
- OAuth lifecycle metadata, expiry, refresh, revoke i health state;
- server-side scope injection dla account/repository/calendar/project;
- allowlista GitLab repositories i Discord owner/guild/channel;
- redaction utilities oraz test fixtures z canary secrets;
- kill switch globalny, per provider i per connection.

## Out of scope

Pełne OAuth UI konkretnych providerów i AgentCore Identity.

## Acceptance criteria

1. Żaden publiczny model/repository DTO nie zawiera tokenu ani secret value.
2. Model-supplied connection/repo ID nie może poszerzyć scope aktualnego case.
3. Private i SonderMind mają rozłączne connection identities i policy context.
4. Revoked/expired connection failuje zamknięcie z jasnym health status.
5. Canary secret nie pojawia się w logach, błędach ani serialized context.
6. Kill switch blokuje nowe efekty bez usuwania audit evidence.

## Required verification

- unit/integration tests scope escalation i redaction;
- test vault failure oraz token refresh race;
- test wszystkich kill switch levels.

## Audit focus

Cross-account leakage, secret lifetime, least privilege, błędy fail-open i zakres
widoczny dla modelu.
