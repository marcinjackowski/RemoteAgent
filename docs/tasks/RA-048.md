# RA-048 — Bounded progressive Engineering execution

**Status:** DONE
**Zależy od:** RA-045
**Milestone:** M9 (iOS Qualification) — `ADR-0011`, `ADR-0015`

## Cel

Zmniejszyć koszt i zwiększyć skuteczność Engineering na wieloplikowych taskach:
automatycznie prowadzić małe slices do wczesnych gates, chronić test-first i
destrukcyjne zmiany, obsłużyć code-owned generatory oraz pozostawić użyteczny,
content-free ślad każdej invocation.

## Kryteria akceptacji

1. MEDIUM/LARGE design ma strict, ordered slice blueprints; runtime wykonuje je
   po kolei, każdy z osobnym required gate/review, i odrzuca szeroki albo obcy
   blueprint przed writer stage.
2. Test-first chronologia jest egzekwowana przed pierwszym trwałym write, a
   baseline/current test evidence nadal jest wymagane.
3. Code-owned generator nie jest narzędziem command modelu; exact receipt i
   świeży fence wiążą executable/config/tree/outputs, a foreign delta lub replay
   bez receiptu fail-closed.
4. Implementacja rezerwuje tury i tokeny na mutację/final report, a read-only
   discovery po przekroczeniu rezerwy jest deterministycznie odmawiane.
5. Kompakcja ogranicza wysyłaną historię bez utraty instrukcji, tool identity,
   exactly-once ani durable raw evidence.
6. Suspicious complete-file/destructive delta jest odrzucony przed receipt i nie
   pozostawia accepted implementation evidence.
7. Osobny JSONL każdej invocation zawiera slice/checklist/gates/budżety/reason
   codes i final outcome; nie zawiera promptu, file/patch bytes, model prose,
   sekretów, host paths ani chain-of-thought.
8. Mutation check każdego mechanizmu czerwieni właściwy test, pełna bramka jest
   niecache'owana i kończy się exit code `0`.
9. Wykonane opt-in smoke MOBL-2023 raportują rzeczywiste provider tokens i wynik
   względem wcześniejszych `236023` tokenów/14 odpowiedzi, bez push/MR/Jira/Discord;
   dalsze live Bedrock calls są wyłączone decyzją właściciela i nie są warunkiem
   domknięcia tego taska.
