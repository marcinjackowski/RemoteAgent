# RA-021 — MCP Tool Broker

## Goal

Zbudować jedyną kontrolowaną bramę pomiędzy agentami a internal/remote MCP tools.

## Scope

- MCP client transport abstraction i version negotiation;
- registry narzędzi z versioned schema, provider, risk tier i capability flags;
- allowlist tool manifest składany per role/case/connection/repository;
- server-side injection owner/scope/connection, niewidoczne dla modelu;
- model arguments validation, output normalization, size limits i provenance;
- read-only tools dla Jira, Gmail, Calendar i GitLab;
- circuit breaker, timeout, rate limit i audit/tool-call ledger;
- traktowanie remote tool descriptions/outputs jako untrusted;
- adapter dla własnych wąskich API tools jako fallback;
- conformance tests dla `tools/list` i `tools/call`.

## Out of scope

External writes, Discord approval i decyzja o konkretnych AgentCore targets.

## Acceptance criteria

1. Model nie może wybrać connection/repo spoza scope przez tool arguments.
2. Role widzą wyłącznie minimalny manifest potrzebny w danym kroku.
3. Remote schema/description nie może nadpisać system policy ani prompt authority.
4. Oversized/malformed output jest ograniczony i zachowany jako artifact evidence.
5. Tool timeout/retry nie zmienia read failure w fałszywy success.
6. Każdy call ma intent, validated args, result digest, latency i trace.

## Required verification

- fake malicious MCP server: schema drift, prompt injection, huge output, timeout;
- cross-scope/repository/account tests;
- protocol/version/transport conformance tests;
- fallback adapter equivalence tests.

## Audit focus

Authority boundary, scope injection, schema drift, output poisoning, retry semantics
i czy model faktycznie nie ma bezpośredniego dostępu do credentiali/MCP.
