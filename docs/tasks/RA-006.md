# RA-006 — Discord case interface

## Goal

Stworzyć prywatny interfejs Discord mapujący eventy i rozmowy na trwałe cases.

## Scope

- bot z owner/guild allowlist i minimalnymi intents/permissions;
- konfiguracja kanałów z Master Planu;
- idempotentne publikowanie root message przez outbox;
- tworzenie, odnajdywanie i ponowne otwieranie threadów;
- trwałe mapowanie case <-> channel/thread/message;
- odbiór wiadomości, komend, przycisków decision/approval i `/stop`;
- pinned/projected case status message;
- rate-limit handling, retry i sanitizacja długości/formatowania;
- fake orchestrator do testów bez Bedrocka.

## Out of scope

Logika modelu, prawdziwe integracje i wykonanie external actions.

## Acceptance criteria

1. Ten sam outbox event nie tworzy dwóch wiadomości ani threadów.
2. Nieautoryzowany user/guild/channel jest ignorowany i audytowany bez danych.
3. Dwa cases mogą prowadzić niezależne rozmowy równolegle.
4. Wiadomości jednego case zachowują kolejność po retry/reconnect.
5. Decision button jest związany z decision ID i checkpoint revision.
6. `/stop` dotyczy wyłącznie wskazanego case.

## Required verification

- contract tests Discord adaptera z recorded fixtures bez sekretów;
- tests reconnect, duplicate delivery, archived thread i rate limit;
- integration test fake event -> thread -> owner response.

## Audit focus

Autoryzacja, dedupe, Discord limits, przypadkowe ujawnienie treści między kanałami
i zachowanie po reconnect.
