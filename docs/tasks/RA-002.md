# RA-002 — Domain contracts and state machines

## Goal

Zdefiniować wersjonowane kontrakty, na których oprą się persistence, agenci,
integracje i Discord.

## Scope

- jedno źródło prawdy dla TypeScript types i runtime JSON Schema;
- `EventEnvelope`, `ExternalEntityRef`, `Case`, `CaseStatus`;
- `CaseCheckpoint`, `AgentRun`, `AgentCompletion`, `DecisionRequest/Answer`;
- `WorkUnit`, role Supervisor/Planner/Implementer/Reviewer/Verification;
- `ToolIntent/Result`, `ExternalAction`, approval i receipt;
- jawne state machines z walidacją dozwolonych przejść;
- canonical JSON i stabilne hashowanie kontraktów wymagających digestu;
- schema fixtures dla backward/forward compatibility.

## Out of scope

Tabele DB, implementacja kolejek, wywołania modelu i provider payload parsers.

## Acceptance criteria

1. Każdy kontrakt odrzuca nieznane pola tam, gdzie jest używany jako granica.
2. Schematy mają `schema_version` i udokumentowaną strategię migracji.
3. Niedozwolone przejście state machine daje typowany błąd bez zmiany stanu.
4. Canonical payload daje identyczny digest niezależnie od kolejności kluczy.
5. External content jest jawnie oznaczone jako trusted/untrusted.
6. Testy pokrywają wszystkie statusy terminalne i przejścia recovery.

## Required verification

- unit/property tests serializacji, digestu i state machines;
- compile-time type tests dla najważniejszych discriminated unions;
- snapshot JSON Schema z uzasadnioną aktualizacją.

## Audit focus

Czy kontrakty nie mieszają danych modelu z autorytatywnym scope, czy są
wersjonowalne i czy późniejsze taski mogą ich używać bez duplikowania typów.
