# RA-035 — Discord UX: loader „Agent pisze…" w wątku

**Status:** DONE  
**Zależy od:** RA-032 (DONE)  
**Milestone:** M7

## Kontekst

Gdy użytkownik napisze wiadomość w wątku KAN-*, agent przetwarza ją w tle przez
kilka sekund, ale w Discordzie nie ma żadnej informacji zwrotnej. Wątek wygląda
jakby nic się nie działo aż do pojawienia się odpowiedzi.

## Decyzja właściciela (2026-08-25)

Loader = **natywny wskaźnik „Bot pisze…"** Discorda (`POST /channels/{id}/typing`),
NIE wiadomość-placeholder. Efemeryczny (~10 s), znika sam, zero śmieci w wątku.
Odrzucone: placeholder edytowany w odpowiedź (złożony) i osobna wiadomość
placeholder (Discord API nie ma delete, zostawia ślad).

## Cel

Na starcie owner-driven passa `case.resume` (zanim ruszy model) worker wyzwala
natywny wskaźnik pisania w wątku case'a. Właściciel widzi „RemoteAgent is typing…"
podczas gdy agent komponuje odpowiedź.

## Kryteria akceptacji

1. Owner-driven `case.resume` (payload `reason: "owner_message"`) enqueue'uje
   `discord.thread_typing`, a dispatcher wyzwala natywny wskaźnik na wątku case'a.
2. Pass, który NIE jest owner-driven (recovery/implementer), NIE emituje wskaźnika
   (nikt nie czeka na wątku).
3. Wskaźnik jest best-effort: brak wątku albo błąd gateway NIE dead-letteruje
   outboxu ani nie blokuje strumienia wiadomości seq; nie tworzy wiadomości ani
   `case_message`, nie rezerwuje seq.
4. Nieudane enqueue wskaźnika w workerze nie failuje passa (try/catch + log).
5. Istniejące testy nie regresują.

## Scope (zrealizowany)

- `packages/discord/src/messages.ts` — event `discord.thread_typing` + payload.
- `packages/discord/src/gateway.ts` — metoda portu `triggerTyping`.
- `packages/discord/src/dispatcher.ts` — routing → `#deliverThreadTyping` (best-effort).
- `apps/discord-bot/src/rest-gateway.ts` — `POST /channels/{threadId}/typing`.
- `packages/discord/src/fakes.ts` — `triggerTyping` w `FakeDiscordGateway`.
- `apps/agent-worker/src/thinking-indicator.ts` — enqueue eventu.
- `apps/agent-worker/src/handlers.ts` — wpięcie w owner-driven `case.resume`.

## Nie w scope

- Zmiana formatu właściwej odpowiedzi (osobna poprawka SUPERVISOR promptu w 1d7138b).
- Reakcja na błędy agenta w wątku (RA-036).

## Ustalenia (dla następnych sesji)

- Worker rozmawia z Discordem WYŁĄCZNIE przez outbox (relay ~1 s). Typing jedzie tym
  samym kanałem, ale best-effort: `#deliverThreadTyping` nigdy nie rzuca (połyka błąd,
  zwraca `delivered`), więc outbox oznacza PUBLISHED i nie dead-letteruje.
- Typing NIE ma seq — jest ortogonalny do uporządkowanego strumienia `thread_message`.
- Discord ma `editMessage`, NIE ma `deleteMessage` ani (wcześniej) `triggerTyping` — tę
  ostatnią dodano w tym tasku (RA-035).
- Regresja z 1d7138b naprawiona przy okazji: `role-context.test.ts` nie przekazywał
  `run` do `createRole.invoke` (mój wcześniejszy commit modelu/promptu poszedł bez pełnej
  bramki). CTF-020 domknięty w rejestrze (fix `3a0c5ed`).
