# RA-035 — Discord UX: loader „Agent pisze…" w wątku

**Status:** READY  
**Zależy od:** RA-032 (DONE)  
**Milestone:** M7

## Kontekst

Gdy użytkownik napisze wiadomość w wątku KAN-*, agent przetwarza ją w tle przez
kilka sekund, ale w Discordzie nie ma żadnej informacji zwrotnej. Wątek wygląda
jakby nic się nie działo aż do pojawienia się odpowiedzi.

## Cel

Gdy worker podejmuje joba `case.resume`, bot powinien od razu wysłać do wątku
wiadomość-placeholder (np. `⏳ Agent is working on it…`). Gdy agent skończy i
`projectCompletionReply` wyśle właściwą odpowiedź, placeholder jest usuwany lub
edytowany.

Dzięki temu właściciel widzi że coś się dzieje, a nie że wiadomość zniknęła
w próżni.

## Kryteria akceptacji

1. Po odebraniu joba `case.resume` przez worker, w wątku Discord pojawia się
   wiadomość-placeholder w ciągu ≤ 2 s.
2. Po zakończeniu agentem pracy, właściwa odpowiedź zastępuje lub następuje
   po placeholderze; placeholder jest usunięty lub wyraźnie zastąpiony.
3. Jeśli agent skończy zanim placeholder zostanie wysłany (race condition),
   nic się nie psuje — placeholder nie zostaje osieroceony na zawsze.
4. Wiadomość-placeholder nie jest trwale przechowywana jako treść biznesowa
   (nie trafia do `case_messages` jako historia konwersacji).
5. Istniejące testy nie regresują.

## Scope

- `apps/agent-worker/src/handlers.ts` lub nowy moduł `discord-thinking.ts`
- `apps/agent-worker/src/completion-reply.ts` (usunięcie placeholdera)
- Możliwe: nowa tabela/kolumna do tymczasowego przechowywania `message_id`
  placeholdera, albo prosty in-memory store per-job z TTL

## Nie w scope

- Zmiana formatu właściwej odpowiedzi (to RA-036 lub osobna poprawka)
- Reakcja na wiadomości błędów (RA-036)
