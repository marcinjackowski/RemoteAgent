# RA-029 — Okablowanie pętli Jira → Discord (routing outboxu + reconciler)

## Goal

Uczynić pełną pętlę **zmiana w Jirze → wiadomość na Discordzie** uruchamialną i
przetestowaną lokalnie. Dziś cała logika środka istnieje, ale trzy seamy composition-root
nie są spięte w żadnym uruchamialnym procesie.

## Dlaczego ten task istnieje

Rozpoznanie `2026-08-23` (podczas lokalnego testowania integracji Jiry) wykazało, że
obserwacja Jiry działa (poll łapie zmiany), ale nic nie zamienia issue w case ani nie
dostarcza wiadomości do Discorda w produkcji. Trzy luki:

1. **Outbox relay nie ma routingu per-aggregat.** `relayOnce` klaimuje dowolny wiersz;
   jedyny prowadzony relay (worker) rzuca na `discord_case`. Rozstrzygnięte w
   [ADR-0009](../decisions/ADR-0009-outbox-aggregate-routing.md): aggregate-scoped relay.
2. **Discord nie prowadzi relayu wyjściowego.** `discord.ts main()` startuje tylko sesję
   wejściową; nic nie konsumuje `discord_case`.
3. **Brak produkcyjnego źródła `discord_case`.** Poll (`jira-poll.ts`) ma `applyIssue`
   będący drukarką; `correlateJiraIssue` nie ma produkcyjnego wołającego.

## Kryteria akceptacji

- **AC1:** `relayOnce`/`Scheduler` przyjmują allow-listę aggregatów; brak listy = obecne
  zachowanie (wstecznie kompatybilne). Klaim filtruje po `outbox.aggregate`. Mutacja
  usuwająca filtr czerwieni test.
- **AC2:** Worker nie klaimuje ani nie DLQ-uje `discord_case` (ani innych nie-swoich
  aggregatów).
- **AC3:** Uruchamialny proces `discord-bot` prowadzi relay ograniczony do `discord_case`
  i dostarcza wiersz przez `DiscordDispatcher` (test z fake gateway: root_thread →
  startThread + sendThreadMessage).
- **AC4:** Periodyczny task w `apps/scheduler` wykonuje `reconcileJiraIssues` z realnym
  `applyIssue` → `correlateJiraIssueInTransaction`; zmiana issue produkuje wiersz outbox
  `discord_case` z `event_type` `discord.root_thread`/`discord.thread_message`.
- **AC5:** Pełna bramka repo zielona (lint, format, typecheck --force, build --force,
  vitest z `RA_REQUIRE_POSTGRES=1`), z liczbą przebiegów.

## Świadome zawężenia (za ADR-0009)

- Dostawa aggregatów `case` i `jira_webhook` — poza zakresem (brak konsumenta dziś, nie na
  ścieżce Jira→Discord; po zmianie zostają `PENDING`, nie DLQ).
- Deploy `scheduler` do CDK — osobny krok wdrożeniowy (nie do zweryfikowania bez AWS);
  RA-029 czyni pętlę uruchamialną i przetestowaną **lokalnie**.
