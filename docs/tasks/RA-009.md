# RA-009 — Multi-agent orchestrator

## Goal

Zbudować trwałego Case Supervisora uruchamiającego role specjalistyczne z
kontrolowaną współbieżnością i jednym writerem.

## Scope

- role registry i ścisłe kontrakty Planner/Implementer/Reviewer/Verification;
- Supervisor state machine wybierający następny work unit;
- per-case mailbox, global/provider semaphores i fairness;
- single-writer lease dla implementera workspace;
- równoległe read-only work units i deterministic merge ich rezultatów;
- bounded iteration/fix budgets, cancellation i pause;
- role-specific prompts jako wersjonowane artefakty;
- audytowalna historia wyboru roli/modelu/toolsetu;
- fake roles do concurrency/recovery tests.

## Out of scope

Prawdziwe narzędzia kodowania, Jira i GitLab.

## Acceptance criteria

1. Dwa cases uruchamiają się równolegle pod kontrolą globalnego limitu.
2. Jeden case nigdy nie ma dwóch aktywnych writerów.
3. Reviewer i Verification mogą działać równolegle wyłącznie read-only.
4. Restart Supervisora wznawia state machine bez powtarzania completed work unit.
5. `WAITING_FOR_USER` kończy bieżący run i poprawnie wznawia po answer event.
6. Wyczerpanie budżetu daje trwały, czytelny checkpoint zamiast pętli.

## Required verification

- deterministic concurrency tests z co najmniej dwoma cases;
- fault injection między work units;
- test single-writer violation, cancellation i fairness;
- snapshots prompt/tool manifestów z review zmian.

## Audit focus

Race conditions, niejawne współdzielenie stanu między rolami, prompt authority,
bounded loops oraz deterministyczność resume.
