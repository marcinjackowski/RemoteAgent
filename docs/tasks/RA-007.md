# RA-007 — Bedrock Converse runtime

## Goal

Zbudować model-neutralny, testowalny adapter Amazon Bedrock obsługujący streaming,
structured output i client-side tool loop.

## Scope

- AWS SDK `Converse` i `ConverseStream` przez wspólny runtime interface;
- IAM/default credential chain w produkcji i jawny lokalny adapter testowy;
- model configuration bez hardcodowania jednego providera;
- tool definitions, `toolUse`, `toolResult` i limit iteracji;
- JSON Schema structured outputs i walidacja `AgentCompletion`;
- tools-disabled repair call dla wadliwego końcowego raportu;
- timeout, cancellation, retry tylko dla bezpiecznych klas błędów;
- usage, latency, request metadata i model identity;
- deterministic fake Bedrock server/adapter dla testów.

## Out of scope

Business tools, MCP, prompts poszczególnych ról i AgentCore Runtime.

## Acceptance criteria

1. Runtime nie polega na server-side conversation memory.
2. Pełna model identity i usage są zapisane przy każdym completion.
3. Niepoprawny schema output jest naprawiany bez ponownego uruchomienia tools.
4. Cancel przerywa stream i pozostawia jednoznaczny status runu.
5. Retry nie powtarza potencjalnego tool side effectu.
6. Model/tool limits kończą pętlę kontrolowanym błędem.

## Required verification

- unit/contract tests text, stream, tool loop, schema repair i cancellation;
- test throttling/transient/fatal error classification;
- test braku credentiali w request logs i exceptions.

## Audit focus

Granice retry, kompletność metadanych, schema validation, cancellation races i
niezależność od jednego modelu.
