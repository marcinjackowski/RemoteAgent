# RA-036 — Discord UX: informacja o błędzie agenta w wątku

**Status:** READY  
**Zależy od:** RA-032 (DONE)  
**Milestone:** M7

## Kontekst

Gdy agent wpadnie w pętlę `AMBIGUOUS` i job trafi do DLQ (max attempts), wątek
Discord milczy — właściciel nie wie czy agent nad tym pracuje czy coś się
zepsuło. Brak widoczności błędów utrudnia diagnostykę i obniża zaufanie do
systemu.

## Cel

Gdy job `case.resume` zostanie dead-lettered (po wyczerpaniu `max_attempts`),
worker lub scheduler wyśle do wątku wiadomość z informacją o błędzie, np.:

> ⚠️ Agent encountered an error and could not complete this task. Please check
> the system logs or try again.

Wiadomość powinna być wyraźnie oznaczona jako błąd (emoji ⚠️ lub 🔴), nie
wyglądać jak odpowiedź agenta, i nie zawierać szczegółów technicznych (stack
trace) — tylko ogólny komunikat bezpieczny do wyświetlenia.

## Kryteria akceptacji

1. Gdy job `case.resume` wyczerpie `max_attempts` i przejdzie do DLQ, w wątku
   Discord pojawia się wiadomość błędu.
2. Wiadomość błędu nie zawiera stack trace ani wewnętrznych ID systemu.
3. Wiadomość błędu jest wyraźnie odróżnialna od normalnej odpowiedzi agenta
   (prefix ⚠️ lub analogiczny).
4. Mechanizm jest idempotentny — wielokrotne przejście do DLQ dla tego samego
   case'a nie tworzy wielu wiadomości błędów.
5. Jeśli case nie ma wątku Discord, błąd jest logowany ale nie crashuje procesu.
6. Istniejące testy nie regresują.

## Scope

- `packages/database/src/repositories/` — DLQ handler lub nowy repo
- `apps/agent-worker/src/` — obsługa DLQ event
- `apps/discord-bot/src/` lub `apps/agent-worker/src/completion-reply.ts`
  — wysyłanie wiadomości błędu do wątku
