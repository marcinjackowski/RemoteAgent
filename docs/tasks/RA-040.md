# RA-040 — Context compiler i trzywarstwowa pamięć

**Status:** BLOCKED_BY_DEPENDENCIES  
**Zależy od:** RA-037, RA-038  
**Milestone:** M8 — `ADR-0011`

## Cel

Budować świeży, stage-specific context packet z manifestem źródeł zamiast
replayować rozmowę; zachować raw evidence, durable knowledge i niewładczą working
projection jako oddzielne warstwy.

## Zakres

- `ContextManifest` z source ID/ref, revision/digest, trust, freshness,
  inclusion reason, byte/token budget i full-artifact reference.
- Packety dla discovery, product/system/program design, slice implementation,
  gate interpretation i review.
- Versioned `MemoryUpdate` związany z checkpoint revision i source watermark.
- Integracja reply-loopu: summary + relewantne recent messages + issue context,
  z pomiarem użycia zamiast stałego `listRecent(20)` replay.
- Bounded inline diff/log, pełne artefakty poza promptem.
- Wspólna redakcja sekretów/PII przed zapisem manifestu/projekcji, złożeniem
  promptu oraz emisją logów/telemetrii.

## Kryteria akceptacji

1. Każdy stage ma allowlistę typów źródeł; test izolacji dowodzi braku wycieku
   między `case_id`, ownerem i integration scope.
2. External/Jira/GitLab/Discord/repo content pozostaje oznaczone
   `UNTRUSTED_DATA`; summary ani źródło nie może zmienić policy, tool scope,
   process class lub gate catalogu. Mutation usuwająca tę granicę daje RED.
3. `checkpoint.summary` jest wersjonowaną projekcją; raw messages/evidence
   pozostają dostępne i mają referencje. Restart między turami odtwarza ten sam
   manifest albo jawnie invaliduje nieświeże źródło.
4. Stage packet nie zawiera pełnej historii. Dobór recent messages jest
   relewancy/budget-aware, a nie wyłącznie oparty o liczbę rekordów.
5. Diff/log powyżej limitu jest skracany na bezpiecznej granicy z markerem;
   digest i referencja prowadzą do pełnego artefaktu.
6. Metryki pokazują input tokens, udział poszczególnych klas źródeł, compaction
   i cache hit; porównanie z baseline reply-loopu jest zapisane w evidence.
7. Fresh session na granicach etapów nie traci aktywnych decyzji ani open issues.
8. Canary secrets/PII i host paths nie występują w packetach, manifestach,
   summary, logach ani telemetry output; mutation wyłączająca redakcję daje RED.
   Manifest zachowuje bezpieczną referencję/digest bez kopiowania sekretu.
9. Bramka taska i `workflow:validate` kończą się exit code `0`.

## Nie w scope

Sterowanie etapami, rzeczywiste komendy i prompt caching jako warunek poprawności.
