# RA-016 — Jira connector

## Goal

Odbierać, normalizować i korelować zdarzenia Jira z coding cases oraz Discordem.

## Scope

- OAuth/admin webhook configuration zgodna z docelowym tenantem;
- weryfikacja webhook authenticity, dedupe i szybki durable ingress;
- parsers: issue create/update/delete, comment i relevant changelog/status;
- JQL/scope filters oraz server-side project allowlist;
- enrichment przez Jira REST do autorytatywnego issue snapshotu;
- issue key -> case/entity correlation i Discord `#jira` routing;
- webhook registration health, expiry metadata i scheduler renewal;
- periodic reconciliation/poll fallback;
- sanitized fixtures i parser contract versioning;
- read-only Jira service methods potrzebne Plannerowi.

## Out of scope

Zmiany Jira wykonywane przez agenta i Atlassian MCP writes.

## Acceptance criteria

1. Duplicate/retried webhook daje jeden normalized event i jedną projekcję.
2. Event spoza project/owner scope jest odrzucony przed enrichment/model call.
3. Sparse webhook jest wzbogacony z provenance, bez nadpisania nowszego stanu.
4. Wygasający webhook generuje renewal job i alert po nieudanym odnowieniu.
5. Reconciliation odnajduje symulowany utracony webhook.
6. Jira content jest oznaczone jako untrusted w context.

## Required verification

- fixtures dla każdego event type i zmian kolejności dostawy;
- contract tests REST pagination/rate limit/auth failure;
- renewal oraz lost-event reconciliation tests;
- e2e fake Jira event -> case -> Discord thread.

## Audit focus

Webhook verification, expiry, ordering, stale enrichment, JQL/project scope oraz
czy parser zachowuje wystarczający kontekst bez kopiowania nadmiaru danych.
