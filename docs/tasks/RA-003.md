# RA-003 — PostgreSQL persistence

## Goal

Zbudować transakcyjne repozytoria i migracje dla trwałego stanu RemoteAgent.

## Scope

- wybór i ADR warstwy SQL/migracji z zachowaniem dostępu do natywnego Postgresa;
- schemat dla owners, connections, raw/normalized events, cases, entities,
  messages, runs, intents/completions, checkpoints, decisions, jobs, outbox,
  workspaces, artifacts, reviews, actions, approvals, receipts i audit log;
- unikalności dla dedupe, optimistic checkpoint revision i external mappings;
- append-only constraints dla ledgerów i audit danych;
- repozytoria z transakcjami oraz domain-level errors;
- lokalny Postgres i migration/test harness.

## Out of scope

Worker kolejek, szyfrowanie secrets payloadów i provider-specific parsers.

## Acceptance criteria

1. Pusta baza migruje od zera i może zostać cofnięta zgodnie z ADR.
2. Ponowne zapisanie tego samego provider eventu nie tworzy duplikatu.
3. Dwie aktualizacje tej samej rewizji checkpointu nie mogą obie wygrać.
4. Nie można powiązać entity/connection z innym owner scope przez zwykły zapis.
5. Append-only rekordy nie mają publicznego update/delete API.
6. Integration tests używają prawdziwego PostgreSQL, nie mocka SQL.

## Required verification

- migrate up/down/up na czystej bazie;
- integration tests transakcji, constraints i konkurencyjnych zapisów;
- test przerwania transakcji bez częściowego stanu.

## Audit focus

Integralność referencyjna, indeksy dla ścieżek hot-path, granice owner/connection,
retencja raw danych oraz możliwość bezpiecznych przyszłych migracji.
