# RA-025 — AWS deployment and disaster recovery

## Goal

Przygotować powtarzalne, least-privilege środowiska AWS i udowodnić backup,
restore, rollback oraz bezpieczne wznowienie pracy.

## Scope

- AWS CDK stacks dla network, compute, ingress, queues/DLQ, PostgreSQL, S3,
  KMS/Secrets, Bedrock access i observability;
- osobne environments/stacks oraz jawne promotion boundaries;
- webhook ingress na skalowalnym HTTP boundary;
- long-lived Discord/worker compute oraz action executor isolation;
- database migrations jako kontrolowany deployment step;
- backups/PITR, S3 lifecycle, secret rotation i IaC state protection;
- deploy/rollback/runbook bez ręcznych niewersjonowanych kroków;
- disaster restore do odrębnego środowiska;
- re-registration/renewal integracji po restore;
- kosztowe limity/budżety i capacity configuration;
- real deploy wyłącznie do jawnie autoryzowanego konta/środowiska.

## Out of scope

Automatyczne wdrożenie do produkcji bez zgody właściciela.

## Acceptance criteria

1. Synth/diff jest deterministyczny i przechodzi security policy checks.
2. IAM roles są rozdzielone per component i nie używają szerokich wildcardów bez ADR.
3. Fresh environment można utworzyć z repo i udokumentowanych prerequisites.
4. Restore drill odtwarza cases/checkpoints/audit i bezpiecznie uzgadnia jobs.
5. Po restore żaden ambiguous write nie jest automatycznie powtórzony.
6. Rollback aplikacji nie cofa destrukcyjnie danych/migracji.
7. Discord, watches/webhooks i secrets mają udokumentowany recovery order.

## Required verification

- CDK synth/diff/tests i policy scanning;
- sandbox deployment smoke test po jawnej zgodzie;
- backup/restore game day;
- region/service failure simulation na poziomie runbooka;
- rollback rehearsal.

## Audit focus

IAM, network egress, public ingress, secret placement, migration/rollback safety,
restore correctness, koszt i brak nieautoryzowanego external deployment.
