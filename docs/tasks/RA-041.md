# RA-041 — Workflow stages w istniejącym SupervisorRuntime

**Status:** BLOCKED_BY_DEPENDENCIES  
**Zależy od:** RA-037, RA-038, RA-039, RA-040  
**Milestone:** M8 — `ADR-0011`

## Cel

Wpiąć risk-proportional product/system/program design i vertical-slice control
flow do istniejącego `SupervisorRuntime` oraz `apps/agent-worker`, z fake roles i
bez prawdziwych zapisów workspace.

## Zakres

- Deterministyczny wybór `SMALL`, `MEDIUM` albo `LARGE_OR_HIGH_RISK` z możliwością
  jawnej decyzji właściciela związanej z checkpoint revision.
- Etapy discovery, outcome, system design, program design, design disposition,
  slice selection, verification disposition i terminal handling.
- Fresh read-only reviewer/design session; brak approval przez autora.
- Limity stage/model calls, deadline, no-progress/oscillation, cancellation i
  durable questions/approvals.
- Jeden production driver: rozszerzenie `SupervisorRuntime`, wiring przez
  `agent-worker`, reużycie istniejącego scheduler/persistence boundary.
- Writer-job identity z RA-034 jest związana z wcześniej claimed unitem:
  `{workUnitId, runId}`; payload nie może utworzyć alternatywnego runu ani writer
  authority.

## Kryteria akceptacji

1. Happy paths trzech klas procesu przechodzą na fake roles i trwałym store;
   każdy pomija tylko etapy dozwolone przez rejestr RA-037.
2. High-risk task nie dociera do implementacji bez zaakceptowanych
   `OutcomeContract`, `SystemDesign`, `ProgramDesign` i wymaganej decyzji
   właściciela/policy.
3. Modelowe `approved` nie wystarcza: kod sprawdza revision, findings, wymagane
   artefakty, gates/evidence preconditions i policy. Mutation usuwająca re-check
   daje fałszywe COMPLETED i RED.
4. Durable question kończy bieżący run bez replayu; odpowiedź materializuje nowy
   run przez trwały event związany z `decision_id`, `parent_run_id` i checkpoint
   revision. Test dowodzi, że niedokończony model call nie jest wznawiany.
5. Crash po model completion jest odzyskiwany z RA-038 bez ponownego wywołania;
   niepotwierdzony wynik pozostaje `AMBIGUOUS`.
6. No-progress/oscillation używa structural fingerprint: tree digest, design/
   slice revision, failed gates i unresolved finding IDs — nie podobieństwa prozy.
7. Cancellation, lease loss, deadline i exhausted mają rozróżnialne terminal
   reasons oraz telemetry IDs.
8. Test architektoniczny i integration test przez `apps/agent-worker` dowodzą,
   że żadna alternatywna ścieżka nie omija `SupervisorRuntime`.
9. Writer payload wskazujący nieclaimed unit, obcy run albo inny case jest
   odrzucany przed pozyskaniem write authority.
10. Bramka taska i `workflow:validate` kończą się exit code `0`.

## Nie w scope

Rzeczywiste wykonanie gates, edycje workspace, commit i live Bedrock/Xcode.
