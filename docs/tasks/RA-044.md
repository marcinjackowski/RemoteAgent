# RA-044 — Kwalifikacja core Engineering Control Plane

**Status:** DONE
**Zależy od:** RA-043  
**Milestone:** M8 — `ADR-0011`

## Cel

Udowodnić na deterministycznych transportach i throwaway repositories, że cały
core działa przez production composition root, przeżywa crash boundaries i nie
pozwala ominąć projektu, policy, writer fence, gates ani review.

## Scenariusze kwalifikacyjne

- `SMALL`: lokalny bug z baseline-red/current-green.
- `MEDIUM`: combined system/program design i minimum dwa slices.
- `LARGE_OR_HIGH_RISK`: product/system/program design, owner approval i slices.
- Crash/restart na każdej granicy intent/completion/receipt/projection.
- Malformed/mismatched model output, stale evidence, failed gate, reviewer
  finding, no-progress, cancellation, deadline i lease loss.
- Cross-case/owner/integration isolation oraz prompt-injection próba poszerzenia
  policy/gates.
- Regresja istniejącego conversational `AgentCompletion`: baseline checkpoint,
  revision advance, `RunCompletionRepository`, outbox i odpowiedź Discord.

## Kryteria akceptacji

1. Wszystkie scenariusze idą przez rzeczywisty `apps/agent-worker` i
   `SupervisorRuntime`; fake są tylko provider/tool boundaries, nie alternatywny
   orchestrator.
2. Restart matrix dowodzi recover-not-replay; nieznany wynik mutującej operacji
   kończy się `AMBIGUOUS`, nigdy `COMPLETED`.
3. High-risk scenario nie zapisuje pliku przed zaakceptowanym `ProgramDesign` i
   approval związanym z właściwą revision.
4. Każdy slice ma kompletny `ContextManifest` i `EvidenceBundle`; receipt dla
   innego drzewa/configu jest odrzucany.
5. Safety mutations co najmniej dla: risk downgrade, writer fence, approval
   re-check, stale evidence i missing required gate dają RED; po przywróceniu
   pełna bramka daje GREEN.
6. Repo-level typecheck/build są uruchomione z `--force`; integracje PostgreSQL
   z `RA_REQUIRE_POSTGRES=1`; niecache'owane wyniki i exit codes trafiają do
   audytu.
7. Obserwowalność pozwala odtworzyć przebieg po `case_id/run_id/op_id/stage/
   attempt` bez czytania modelowego chain-of-thought.
8. Dokument kwalifikacji wymienia ograniczenia core i wymagania środowiska iOS;
   nie deklaruje live Xcode bez uruchomionego RA-045.
9. Dotychczasowy reply-loop zachowuje semantykę completion/checkpoint/outbox i
   odpowiedzi Discord; M8 nie przechwytuje go równoległą ścieżką.
10. Pełna bramka taska i `workflow:validate` kończą się exit code `0`.

## Nie w scope

AWS/live Bedrock, realny `sondermind-ios`, push, MR i merge.
