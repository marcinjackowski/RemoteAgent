# RA-015 — Independent review and fix loop

## Goal

Wprowadzić niezależny, bounded review/fix loop przed publikacją zmian.

## Scope

- Reviewer działa w świeżym model context i nie posiada write tools;
- structured `ReviewReport` z severity, lokalizacją, evidence i required fix;
- input: task, decisions, plan, diff, repo instructions, test/snapshot evidence;
- rozróżnienie blocker/high/medium/low/nit i false-positive disposition;
- Supervisor kieruje wymagane findingi do Implementera;
- każda iteracja ponownie uruchamia adekwatne testy i delta review;
- limit iteracji/budżetu oraz eskalacja do właściciela;
- opcjonalne równoległe review i Verification z deterministycznym merge wyników;
- final readiness report.

## Out of scope

GitLab review comments, push/MR i security penetration testing.

## Acceptance criteria

1. Reviewer nie może modyfikować kodu ani checkpoint authority fields.
2. PASS review wymaga braku unresolved BLOCKER/HIGH/MEDIUM.
3. Finding bez lokalizacji/evidence nie może automatycznie blokować pracy.
4. Fix loop ma jawny maksymalny limit i nie może trwać bez końca.
5. Każdy resolved finding wskazuje diff/test evidence poprawki.
6. Reviewer nie ufa opisowi Implementera zamiast rzeczywistego diffu.

## Required verification

- fixture diffs z prawdziwym błędem, false positive i conflicting reviews;
- role capability tests potwierdzające read-only;
- bounded loop, budget exhausted i resume tests.

## Audit focus

Niezależność review, możliwość rubber-stampingu, severity policy, merge raportów i
czy poprawki faktycznie wracają przez single writera.
