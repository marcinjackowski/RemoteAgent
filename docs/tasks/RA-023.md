# RA-023 — AgentCore Gateway and official MCP targets

## Goal

Zweryfikować i, gdzie bezpieczne, wdrożyć AgentCore Gateway/Identity jako managed
MCP boundary dla oficjalnych provider servers.

## Scope

- IaC/spike AgentCore Gateway z inbound auth i fine-grained policy hook;
- outbound OAuth/credential provider lifecycle niewidoczny dla modelu;
- target evaluation: Atlassian Rovo MCP, Google Gmail/Calendar MCP, GitLab MCP;
- opcjonalny Slack MCP wyłącznie jako dodatkowe narzędzie, nie UI systemu;
- capability/schema/status matrix z uwzględnieniem Preview/Beta;
- mapping Gateway tools do lokalnego risk registry i hidden scope injection;
- revocation, token refresh, tool discovery drift i audit integration;
- fallback do custom adaptera per provider;
- mały AgentCore Runtime/session-storage spike dla `WorkspaceRunner` i ADR
  adopt/defer/reject bez uzależniania checkpointów od sesji Runtime.

## Out of scope

Usunięcie własnych ingress connectorów i przeniesienie source of truth do AgentCore.

## Acceptance criteria

1. Każdy provider ma udokumentowany werdykt adopt/defer/reject i dowody.
2. Preview/Beta target posiada działający, testowany fallback.
3. Gateway policy nie może poszerzyć lokalnej policy ani owner/case scope.
4. OAuth revoke i tool schema drift są wykrywane i powodują fail-closed.
5. Model nie otrzymuje refresh/access tokenów.
6. AgentCore Runtime restart nie traci case state, bo odtwarza go z Postgresa.

## Required verification

- contract tests live tylko po jawnej autoryzacji właściciela;
- mocked auth refresh/revoke i schema drift tests;
- policy/scope tests lokalny broker -> Gateway -> target;
- Runtime stop/resume spike z zewnętrznym checkpointem.

## Audit focus

Vendor lock-in, maturity usług, OAuth isolation dla dwóch Google accounts,
podwójna warstwa policy, audit completeness i jakość fallbacków.
