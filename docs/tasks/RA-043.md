# RA-043 — Vertical-slice executor, GitLifecycle i review loop

**Status:** BLOCKED_BY_DEPENDENCIES  
**Zależy od:** RA-041, RA-042  
**Milestone:** M8 — `ADR-0011`

## Cel

Wykonać jeden zaakceptowany `SliceContract` przez jedynego writera, zebrać
rzeczywisty diff i gates, przeprowadzić niezależne review, a dopiero po pełnym
zakończeniu utworzyć lokalny commit przez istniejący `GitLifecycle`.

## Zakres

- Per-case worktree i `WorkspaceFenceValidator` związany z writer lease/fencing
  tokenem; wejście z RA-034 (`implementer-work.ts`, `workspace-config.ts`).
- Edycje wyłącznie przez `implementation-tools` w allowed paths slice'a.
- Po każdym slice: actual tree/diff → RA-042 gates → istniejący read-only,
  diff-bound `review-loop` → correction/next/stop.
- Deterministyczny branch i lokalny evidence-bound commit przez `GitLifecycle`.
- Zero push/MR/merge w tym tasku.

## Kryteria akceptacji

1. E2E na throwaway repo wykonuje co najmniej dwa pionowe slices; każdy ma
   niezależny observable result, diff, gates i review przed następnym.
2. Brak/stary fence, allowed-path violation albo drugi writer dla `case_id`
   odrzuca write przed zmianą drzewa; guard ma mutation RED→GREEN.
3. Worker report nie jest źródłem prawdy: changed files/diff/tree digest są
   odczytywane z workspace i porównywane z raportem.
4. Reviewer nie ma write tools, dostaje fresh context i diff związany z tree
   digestem. HIGH/MEDIUM finding blokuje przejście do final completion.
5. Correction zachowuje identity slice'a i zwiększa attempt; oscillation/
   no-progress kończy run zamiast nieskończonego fix loopu.
6. Commit jest tworzony przez realny `GitLifecycle`, z branch policy, disabled
   hooks, evidence binding i receipt; test dowodzi, że target-controlled config
   nie poszerza zachowania.
7. Push, MR i merge są nieosiągalne przez tę ścieżkę.
8. Bramka taska i `workflow:validate` kończą się exit code `0`.
