# RA-001 — Repo foundation

## Goal

Utworzyć minimalny, powtarzalny fundament monorepo, na którym wszystkie kolejne
taski mogą bezpiecznie budować.

## Scope

- `pnpm` workspaces, przypięte wersje runtime/package managera i Turborepo;
- strict TypeScript, wspólne konfiguracje lint/format/typecheck/test/build;
- szkielety aplikacji i pakietów wymienionych w Master Planie bez logiki domenowej;
- Vitest oraz konwencja unit/integration/e2e;
- lokalny Docker Compose dla zależności infrastrukturalnych;
- GitLab CI uruchamiający install, lint, typecheck, test i build;
- podstawowe reguły dependency boundaries i zakaz importów apps -> apps;
- `workflow:validate` sprawdzający task IDs, linki, statusy, zależności, cykle i
  zgodność wymaganych handoff/audit files z przejściami statusów;
- ADR dokumentujący wersje i kluczowe wybory toolingowe.

## Out of scope

Modele domenowe, baza danych, Bedrock, Discord i prawdziwe integracje.

## Acceptance criteria

1. Clean checkout można zainstalować jednym udokumentowanym poleceniem.
2. Root commands `lint`, `typecheck`, `test` i `build` działają deterministycznie.
3. Każdy planowany app/package ma minimalny manifest i jest widoczny dla workspace.
4. CI używa lockfile i nie pobiera sekretów do podstawowych kontroli.
5. TypeScript strict oraz dependency boundaries mają celowo failing fixture/test.
6. Repo nie zawiera skopiowanych credentiali ani lokalnych danych z `../Private`.
7. Niepoprawny status, brak task file, cykl zależności albo brak handoffu/audytu
   powoduje błąd `workflow:validate`.

## Required verification

- instalacja z lockfile;
- lint, typecheck, unit tests i build z root;
- walidacja workspace graph;
- pozytywne i negatywne fixtures dla `workflow:validate`;
- skan nazw/formatów typowych sekretów na plikach śledzonych przez Git.

## Audit focus

Reprodukowalność, brak niepotrzebnych zależności, hermetyczność konfiguracji oraz
czy task nie przemycił przedwcześnie logiki produktowej.
