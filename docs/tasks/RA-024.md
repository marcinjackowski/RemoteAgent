# RA-024 — Security, privacy and observability hardening

## Goal

Przeprowadzić przekrojowe hardening przed wdrożeniem: zagrożenia agentowe,
prywatność, telemetry, koszty i operacyjne kill switches.

## Scope

- aktualny threat model i trust-boundary diagrams;
- prompt injection/redaction/exfiltration test suite;
- least privilege review wszystkich IAM/OAuth/Discord/GitLab scopes;
- retention, export, delete i backup classification per data class/connection;
- OpenTelemetry traces event -> case -> run -> tool -> action -> receipt;
- metryki queue lag, retry, lease, DLQ, watch expiry, Bedrock usage/cost/latency;
- structured logs z correlation IDs i redaction;
- alerts, dashboards, health/readiness i operator runbooks;
- load/backpressure/rate-limit tests;
- dependency/container/IaC scanning oraz SBOM;
- kill switch drill i incident evidence preservation.

## Out of scope

Docelowe AWS production deployment i disaster restore drill.

## Acceptance criteria

1. Threat model obejmuje każdą zewnętrzną granicę i data flow.
2. Canary secrets/PII nie pojawiają się w logs, traces ani model context.
3. Cross-account/repo prompt injection tests pozostają ograniczone przez policy.
4. Alerty obejmują DLQ, renewal failure, stale lease i cost anomaly threshold.
5. Retention/delete nie niszczy wymaganych minimalnych audit receipts bez reguły.
6. Kill switch drill zatrzymuje effects, zachowując odczyt i dowody.
7. System zachowuje kontrolowany backpressure zamiast przeciążenia providerów.

## Required verification

- security/adversarial suite;
- load test i provider rate-limit simulation;
- redaction/canary scan całej telemetry pipeline;
- manual threat-model review oraz kill-switch exercise;
- dependency/IaC/container scans.

## Audit focus

Audyt przekrojowy, nie tylko kod taska: authorization, leakage, injection,
retention, telemetry gaps, kosztowe pętle i operacyjna możliwość zatrzymania.
