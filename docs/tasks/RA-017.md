# RA-017 — GitLab connector and Merge Requests

## Goal

Połączyć allowlisted repozytoria z cases, obsłużyć zdarzenia GitLab oraz bezpieczny
push case brancha i utworzenie draft Merge Request.

## Scope

- GitLab connection/repository allowlist i project identity mapping;
- signed webhook verification, timestamp/replay protection i idempotency;
- parsers: MR, issue, note, push, pipeline i job;
- correlation branch/MR/pipeline -> istniejący case;
- read API potrzebne Plannerowi/Reviewerowi;
- remote branch push przez credential broker niewidoczny dla modelu;
- idempotentne create/find/update draft MR;
- MR description z taska, decyzji, zmian, tests i review evidence;
- pipeline status/log artifact ingestion oraz Discord `#gitlab`/case routing;
- real writes disabled by default poza skonfigurowanym sandbox project/scope grant.

## Out of scope

Merge MR, force-push, produkcyjny deploy i ogólny approval engine z RA-022.

## Acceptance criteria

1. Repo/project spoza allowlisty nie może być odczytane ani zmienione.
2. Ponowienie push/create MR nie tworzy duplikatu MR.
3. Token GitLab nie trafia do modelu, command outputu ani remote URL logu.
4. Pipeline event aktualizuje właściwy case i commit SHA.
5. Webhook replay/stary timestamp jest odrzucony i audytowany.
6. Draft MR zawiera prawdziwe test/review evidence i unresolved risks.

## Required verification

- fake GitLab API/webhook contract tests;
- sandbox project integration test, jeżeli credentials są jawnie dostępne;
- duplicate MR/push, auth failure, rate limit i pipeline ordering tests;
- secret redaction test dla Git URLs/errors.

## Audit focus

Repository scope, credential leakage, remote idempotency, webhook signatures,
powiązanie SHA oraz bezpieczeństwo write feature flag.
