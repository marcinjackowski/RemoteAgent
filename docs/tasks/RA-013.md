# RA-013 — Tests, artifacts and snapshots

## Goal

Uruchamiać weryfikację deterministycznie i przechowywać dowody niezależne od
deklaracji modelu.

## Scope

- versioned test command manifest pochodzący z repo profile/planu;
- runner lint/typecheck/unit/integration/build/custom z timeoutami;
- `TestRun` z command, cwd, environment fingerprint, exit code, duration i SHA;
- artifact store interface: local filesystem oraz przyszły S3 adapter;
- log redaction, bounded excerpts i link/reference do pełnego artefaktu;
- code coverage metadata;
- snapshot test diff discovery i classification;
- workspace snapshots/tree digest przed/po fazie;
- Verification role interpretująca wyniki bez możliwości fałszowania result.

## Out of scope

Independent code review, Git commit i provider CI pipeline.

## Acceptance criteria

1. Model nie może zapisać `PASS` bez powiązanego successful `TestRun` receipt.
2. Każdy wynik jest związany z konkretnym workspace i commit/tree digest.
3. Snapshot update zawiera diff oraz uzasadnienie expected change.
4. Timeout/cancel/OOM różnią się od zwykłego failed assertion.
5. Sekrety są redagowane w excerptach i pełnych przechowywanych logach.
6. Retention/size limits nie usuwają metadanych audytowych wyniku.

## Required verification

- fixture suites: pass, fail, flaky simulation, timeout, huge output, secret output;
- snapshot changed/unchanged/unapproved tests;
- artifact integrity/digest tests.

## Audit focus

Wiarygodność evidence, binding do kodu, snapshot rubber-stamping, redakcja i
rozróżnienie błędów infrastruktury od regresji.
