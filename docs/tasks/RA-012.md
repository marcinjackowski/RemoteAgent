# RA-012 — Implementation toolset

## Goal

Umożliwić Implementerowi kontrolowane czytanie, modyfikowanie i sprawdzanie kodu
bez przekazywania mu nieograniczonego host shell.

## Scope

- tools: list/read/search, apply patch, mkdir w scope, diagnostics i bounded command;
- walidacja każdej ścieżki względem workspace root;
- command policy: cwd, timeout, env allowlist, network mode i output limits;
- redakcja outputu przed zapisaniem/logowaniem/przekazaniem modelowi;
- operation intent, pre/post tree digest, changed files i result envelope;
- ochrona plików repo instructions, credential paths i system configuration;
- Implementer role korzystający wyłącznie z narzędzi bieżącego case;
- idempotentne ponowne odczyty i bezpieczne wykrycie częściowego patcha.

## Out of scope

Semantyka test suite, Git commit/push, reviewer i external MCP.

## Acceptance criteria

1. Path traversal, symlink escape i cwd escape są blokowane.
2. Command nie może wstrzyknąć własnych sekretów ani poszerzyć network policy.
3. Każda zmiana ma intent, wynik, pre/post digest i listę plików.
4. Truncated output zachowuje pełny artefakt poza promptem i wskazuje truncation.
5. Nieudany/częściowy patch pozostawia wykrywalny stan, nie fałszywy success.
6. Implementer nie może zmienić scope przez argument toola.

## Required verification

- adversarial path/command/env/output tests;
- integration tests edit -> digest -> resume;
- canary secret redaction tests;
- cancellation podczas command i patch boundaries.

## Audit focus

Sandbox/tool escape, command injection, secret exposure, poprawność intent ledger i
zdolność recovery po częściowej zmianie.
