# RA-004 — Durable jobs, outbox and leases

## Goal

Zapewnić co najmniej once delivery bez duplikowania efektów oraz bezpieczne
wznowienie po awarii workera.

## Scope

- transactional outbox API;
- durable job state, attempt history, retry policy i DLQ;
- leases z expiry, heartbeat i fencing tokenem;
- per-case serialization oraz konfigurowalny global/provider concurrency limit;
- intent-before-operation i completion envelope;
- reconciliation dla `AMBIGUOUS`;
- scheduler interface dla polling/renewal;
- deterministic clock/id generator w testach.

## Out of scope

Konkretny Discord/provider worker oraz AWS deployment.

## Acceptance criteria

1. Commit stanu i outbox message jest atomowy.
2. Crash po intent, przed completion nie powoduje automatycznego replay write.
3. Wygasły worker nie może zapisać wyniku po przejęciu lease przez nowego workera.
4. Dwa joby jednego case wykonują się sekwencyjnie, a różnych cases równolegle.
5. Retry ma bounded exponential backoff i kończy w obserwowalnym DLQ.
6. Reconciliation jest idempotentne i audytowalne.

## Required verification

- integration tests z dwoma workerami;
- fault injection w granicach commit/publish/start/complete;
- test lease expiry i stale fencing token;
- test retry oraz DLQ.

## Audit focus

Race conditions, transakcyjne granice, clock assumptions i ryzyko podwójnych
side effectów.
