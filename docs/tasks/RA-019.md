# RA-019 — Gmail two-account connector

## Goal

Niezawodnie odbierać zmiany z prywatnego i SonderMind Gmaila bez mieszania
credentiali, danych, kanałów ani kontekstu agentów.

## Scope

- dwa oddzielne OAuth connections i jawne account aliases;
- Gmail `watch` do Google Pub/Sub oraz bezpieczny subscription receiver;
- cursor per account oparty o `historyId` i `history.list`;
- codzienny renewal watch oraz alert przed/po expiration;
- periodic reconciliation fallback dla opóźnionych/utraconych notification;
- full resync path dla invalid/expired history cursor;
- thread-centric parsers: message add/delete, labels i thread metadata;
- kontrolowane pobieranie body/headers/attachments z privacy limits;
- routing do `#gmail-private` i `#gmail-sondermind`;
- read tools i create-draft capability pozostające za policy boundary.

## Out of scope

Automatyczne wysyłanie maili i produkcyjne Google MCP.

## Acceptance criteria

1. Notification zawierająca tylko history ID poprawnie odtwarza zmiany.
2. Duplicate/out-of-order notifications nie duplikują eventów ani wiadomości.
3. Watch każdego konta jest odnawiany niezależnie i ma health status.
4. Lost notification jest odnalezione przez reconciliation.
5. Private event nigdy nie trafia do SonderMind channel/context i odwrotnie.
6. Attachment/body nie są pobierane ani logowane bez potrzeby i provenance.
7. Invalid history cursor prowadzi do kontrolowanego resync bez utraty audit trail.

## Required verification

- Pub/Sub/watch/history fixtures dla dwóch kont;
- duplicate, out-of-order, dropped notification i cursor expiry tests;
- cross-account adversarial tests;
- OAuth revoke/refresh/rate-limit tests;
- e2e notification -> case/thread -> Discord channel.

## Audit focus

Account isolation, cursor correctness, watch renewal, privacy/retention, parser
MIME edge cases i odporność na prompt injection w mailach.
