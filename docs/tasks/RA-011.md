# RA-011 — Repository discovery and planning

## Goal

Dać Plannerowi kompletny, wersjonowany obraz repozytorium oraz plan możliwy do
audytu i późniejszego wznowienia.

## Scope

- bezpieczne odkrywanie instrukcji `AGENTS.md`, scoped variants, README,
  CONTRIBUTING, manifestów, CI i test commands;
- reguły pierwszeństwa instrukcji oraz wykrywanie konfliktów;
- versioned `RepositoryProfile` związany z base SHA;
- read-only narzędzia search/read/tree/symbol/config inspection;
- structured `ImplementationPlan`: wymagania, kroki, pliki/obszary, test plan,
  ryzyka, decyzje i definition of done;
- Planner role i `DecisionRequest` dla materialnych niejasności;
- detekcja zmiany base SHA/instrukcji wymagającej re-planowania.

## Out of scope

Edycja kodu, wykonywanie planu i Git commit.

## Acceptance criteria

1. Wszystkie obowiązujące repo instructions są wykryte i mają provenance.
2. Plan mapuje każdy wymóg taska na krok i test/evidence.
3. Prompt-injection-like tekst w repo jest danymi, nie nowym system authority.
4. Zmiana instrukcji albo base SHA unieważnia stale plan według jawnych reguł.
5. Plan z materialną niejasnością kończy się decyzją, nie dowolnym wyborem.
6. Planner nie ma narzędzi zapisujących.

## Required verification

- fixture repos z nested instructions, konfliktem i złośliwą treścią;
- schema/golden tests RepositoryProfile i planu;
- test stale plan po zmianie SHA/instruction digest.

## Audit focus

Instruction precedence, prompt injection, kompletność requirement mapping i brak
ukrytych write capabilities Plannera.
