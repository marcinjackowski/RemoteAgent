# RA-037 — Engineering workflow contracts i granica control plane

**Status:** DONE  
**Zależy od:** —  
**Milestone:** M8 — `ADR-0011`

## Cel

Zdefiniować czysty, strict model domenowy human-steered engineering workflow
oraz dowieść, że M8 rozszerza istniejący `SupervisorRuntime`, zamiast tworzyć
drugi orchestrator lub źródło prawdy.

## Zakres

- Inwentarz i mapa odpowiedzialności istniejących: `agent-orchestrator`,
  `repository-planner`, `review-loop`, `test-evidence`, `workspace-runner`,
  `git-lifecycle`, `bedrock-runtime` i `agent-worker`.
- Strict, versioned kontrakty:
  - `ProcessClass`: `SMALL | MEDIUM | LARGE_OR_HIGH_RISK`;
  - `OutcomeContract`, `SystemDesign`, `ProgramDesign`, `SliceContract`;
  - `ContextManifest`, `EvidenceBundle`, `MemoryUpdate`;
  - decyzje design/review/verification i terminal reasons.
- Deterministyczna polityka minimalnej klasy procesu. Model może zaproponować,
  ale nie może obniżyć wymaganej klasy ani gates.
- Jawny graf etapów dla trzech klas procesu oraz rejestry stage→contract,
  stage→role i stage→artifacts.
- Kanoniczny hash versioned JSON używany przez dalsze taski.

## Kryteria akceptacji

1. Każdy kontrakt odrzuca nadmiarowe pola, koercję typów i semantycznie
   niekompletny obiekt; mutation usuwająca load-bearing validator daje RED.
2. `ProgramDesign` wymaga co najmniej: call-flow, file-tree delta, kluczowych
   typów/sygnatur, niepewności, oczekiwanych testów i kolejności slices.
3. `SliceContract` ma dokładnie jeden obserwowalny rezultat, allowed paths,
   gate IDs, inspection method i stop condition; gate jest ID, nie komendą.
4. Polityka ryzyka wymusza `LARGE_OR_HIGH_RISK` dla security/policy, migracji,
   nieodwracalnych side effectów i zmian szerokich kontraktów; modelowa próba
   downgrade'u jest odrzucana.
5. Graf etapów pomija zbędne fazy dla `SMALL`, ale nie pozwala ominąć gates,
   evidence ani review.
6. Test architektoniczny potwierdza, że nie powstał drugi production driver,
   kolejka ani autorytatywna state machine obok `SupervisorRuntime`.
7. `EngineeringPhase` jest kontraktem durable payload/projection; jego moduł nie
   wystawia publicznego claim/enqueue/transition/finalize niezależnego od
   `SupervisorRuntime`.
8. Kanoniczny hash jest niezależny od kolejności kluczy i związany z wersją
   schematu.
9. Bramka taska i `workflow:validate` kończą się exit code `0`.

## Nie w scope

DB, Bedrock, model prompts, wykonanie komend, edycja workspace i live iOS.
